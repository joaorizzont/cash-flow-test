# ADR-0013: Node.js, TypeScript and Fastify

- **Status:** Accepted
- **Date:** 2026-10-09

## Context

The challenge allows any language. The services are I/O bound (HTTP, database, broker, cache) with simple computation. The code must be strongly typed to model money and dates safely, easy to test without infrastructure, and quick to start in containers.

## Decision

| Choice                         | Reason                                                                                                    |
| ------------------------------ | --------------------------------------------------------------------------------------------------------- |
| Node.js 22 LTS                 | Non-blocking I/O suited to APIs and queue consumers; long-term support                                    |
| TypeScript in strict mode, ESM | Static types for domain modelling (`noUncheckedIndexedAccess`, strict null checks)                        |
| Fastify 5                      | High throughput, JSON Schema validation, pino logging built in, `inject` for tests without opening a port |
| TypeBox + type provider        | One schema validates the request, types the handler and generates OpenAPI (`/docs`)                       |
| Zod for configuration          | The process fails fast at startup when misconfigured                                                      |
| `pg` with explicit SQL         | See [ADR-0004](0004-postgresql-database-per-service.md)                                                   |
| UUID v7                        | Time-ordered identifiers keep B-tree inserts local; generated by the application before persisting        |
| Vitest, Testcontainers, k6     | Fast unit tests, integration tests against real dependencies, load tests against the full environment     |
| ESLint (strict) + Prettier     | Rules reinforcing Clean Code: max complexity 8, max 3 parameters, no inline comments                      |
| npm workspaces monorepo        | Two services and the contracts package in one repository, built by one multi-stage Dockerfile             |

Code has no comments: intent is expressed through names, small functions and these ADRs.

## Alternatives considered

| Alternative         | Why it was not chosen                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------ |
| Java / Spring, .NET | Would support the same design; the choice followed language proficiency and fast iteration |
| Go                  | Excellent for this workload; less expressive for rich domain modelling with value objects  |
| Express             | Slower and without native schema validation                                                |
| NestJS              | Opinionated module system and decorators; heavier than the scope needs                     |
| Jest                | Needs extra configuration for native ESM                                                   |

## Consequences

**Positive**

- One language across both services, the contracts package, tests and the load and resilience tooling.
- Measured performance is far above the requirement (400 req/s on one replica without errors).

**Negative / trade-offs**

- Node.js is single-threaded per process; CPU-heavy work would need worker threads or horizontal scaling (not the case here).
- ESM with TypeScript requires care with module resolution (`NodeNext`, `.js` import suffixes, a custom export condition for the contracts package).
